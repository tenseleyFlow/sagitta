# AI completion and privacy

AI is off by default. Turning it on is a disclosure and policy decision, not
an automatic consequence of configuring a backend. A local loopback backend
and a remote backend have distinct consent; a workspace has its own
allow/deny/ask grant.

The authoritative byte-level disclosure is [AI and your privacy](../ai-privacy.md).
In summary, a request may contain bounded prefix/suffix text around the
cursor, the workspace-relative path, detected language, model, and generation
settings. It does not contain absolute paths, other buffers, workspace file
lists, Git remotes, editor state, or telemetry.

## Safe setup

Use the shipped local or cloud preset as a starting point, then inspect the
resulting Fletch configuration. Select credentials indirectly through
`key_env` or `key_cmd`; literal credentials in backend configuration are
rejected.

```fletch
set({
    "ai.enable": false,
    "ai.default_workspace": "ask",
    "ai.on_redact": "block",
})
```

Cloud context is scanned against the shipped secret rules before a request
body or transport exists. A match blocks the whole remote request. Loopback
context may elide the matched span under policy. Excluded paths are rejected
before their content is read. Workspace configuration cannot set a weaker
redaction policy than global user configuration.

## Backends and requests

Backends are registered Fletch data describing URL, protocol adapter, model,
headers, credential source, and timeouts. Native HTTP handles supported plain
or TLS routes where available; the curl adapter uses a fixed argv and a
private config file so secrets never appear in process arguments.

Streams are parsed incrementally as SSE, NDJSON, or whole-body responses.
Cancel aborts the transport, retires callbacks by generation, and prevents a
late byte from reaching the buffer. Accepted ghost text is one owned undo
transaction.

## Logs and retained state

Normal logs contain backend names, timings, byte counts, and error classes,
not bodies or authorization values. Body logging requires both
`YEW_AI_DEBUG=1` and `ai.debug_bodies = true` and warns once. Statistics are
local counters and latency summaries. yew has no telemetry, crash upload, or
usage analytics.

Once bytes reach a remote provider, yew cannot control retention, training,
or later access. Provider policy must be evaluated separately and can change.
