# Theme Author's Manual

Themes are pure Fletch data. They contain no calls, imports, functions, or
capabilities, and loading one never executes code. A theme file contains one
map literal and normally lives at `themes/NAME.fl`.

Yew ships `quiver-dark` and `quiver-light`. Both define all 54 semantic
attributes explicitly. A user theme may be partial; its missing attributes
follow the fallback chain in `.docs/syntax-def.md`, resolved once at load.

## Top-level map

| Key | Type | Required | Meaning |
|---|---|---:|---|
| `theme` | int | yes | Schema version; the only accepted value is `1`. |
| `name` | string | yes | Theme id and filename stem. |
| `kind` | string | yes | `"dark"` or `"light"`; used by automatic selection. |
| `palette` | map | yes | Named colors referenced as `"@name"`. |
| `ui` | map | yes | Editor-chrome styles and the underline palette. |
| `attrs` | map | yes | Semantic syntax-attribute styles. |

Unknown top-level, style, and underline-palette keys are errors with source
carets. Files larger than 1 MiB are rejected. A failed load leaves the active
theme unchanged.

## Colors and palettes

A color field accepts exactly one of these forms:

```fletch
fg: "#c8ccd4"       # six-digit RGB
fg: "@foreground"   # palette reference; references may be transitive
fg: { idx: 12 }      # ANSI/indexed color 0..255
fg: "none"           # terminal default (SGR 39 or 49)
```

Palette cycles and unknown references are errors. Indexed colors are retained
as indexed colors; RGB values are converted deterministically for the 256- and
16-color tables when the theme loads.

## Attribute styles

`attrs` keys are the closed 54-name vocabulary in `.docs/syntax-def.md`.
Each value is a style map:

| Field | Type | Default | Meaning |
|---|---|---|---|
| `fg`, `bg` | color | `"none"` | Foreground and background. |
| `bold` | bool | `false` | Bold/intense. |
| `italic` | bool | `false` | Italic. |
| `underline` | bool | `false` | Straight underline. |
| `undercurl` | bool | `false` | Curly underline where supported, straight otherwise. |
| `strike` | bool | `false` | Strikethrough. |
| `dim` | bool | `false` | Faint/dim. |
| `reverse` | bool | `false` | Swap foreground and background. |
| `c256` | int 0..255 | converted `fg` | Explicit 256-color foreground override. |
| `c16` | int 0..15 | converted `fg` | Explicit ANSI foreground override. |
| `ul` | string | foreground | Underline color selector: `error`, `warn`, or `info`. |
| `mono` | string | `plain` | `plain`, `bold`, `italic`, `underline`, `reverse`, or `dim`. |

An omitted attribute inherits its fallback attribute's fully resolved entry,
transitively. An attribute that is present is a complete style: omitted fields
inside that map take the defaults above. The compiler materializes flat
64-entry truecolor, 256-color, 16-color, monochrome, and dumb-terminal tables;
rendering never walks the fallback chain or converts a color.

## UI and underline colors

UI roles use the same color and boolean style fields. Common roles are `bg`,
`fg`, `sel`, `cursor`, `cursor.secondary`, `gutter`, `gutter.cursor`, the
`mode.*` roles, and `search.match` / `search.current`.

`ui.ul` is required and defines exactly three colors:

```fletch
ui: {
    ul: {
        error: "#ff5f5f",
        warn:  "#e5c07b",
        info:  "#61afef",
    },
}
```

At truecolor, an underlined style with `ul` emits its selected color. At lower
tiers the underline uses the foreground color. The three selectors occupy the
cell attribute field without enlarging `Cell`.

## Discovery and switching

For a requested `NAME`, yew checks these locations in order:

1. `$XDG_CONFIG_HOME/yew/themes/NAME.fl` (or `~/.config/yew/themes/NAME.fl`)
2. `$YEW_RUNTIME_DIR/themes/NAME.fl`
3. the installed runtime directory
4. `runtime/themes/NAME.fl` for an uninstalled source-tree run

Theme names contain lowercase ASCII letters, digits, hyphens, and underscores.
Themes are intentionally not cached to disk: they are small, pure data, and
compile in microseconds. Switching replaces the resolved tables and repaints;
syntax spans and syntax-engine state do not change.

Set a theme with `:theme NAME`, `ed.theme.set`, `set { theme: "NAME" }`,
`YEW_THEME=NAME`, or `yew --theme NAME`. The command-line flag wins over the
environment, and both override configuration for that run. Use
`ed.theme.toggle` to switch between the last selected dark and light themes.

`set { theme_auto: true }` asks the terminal for its background with OSC 11 at
startup and selects the last theme of the matching `kind`. It is off by
default, observes the bounded terminal-probe timeout, and leaves the configured
theme unchanged when the terminal does not answer or returns a malformed
reply. An explicit `YEW_THEME` or `--theme` still wins over automatic choice.

## Degradation ladder

The ladder is decided once per frame:

| Condition | Result |
|---|---|
| `TERM=dumb` | Terminal-default colors and no style attributes. |
| `NO_COLOR` present, including an empty value | Terminal-default colors; each attr uses only its `mono` rendition. |
| `YEW_COLORS=16` or a 16-color terminal | `c16`, otherwise deterministic nearest ANSI. |
| `YEW_COLORS=256` or a 256-color terminal | `c256`, otherwise `yew_rgb_to_256`. |
| Truecolor terminal | RGB values verbatim. |

`NO_COLOR` preserves structure rather than color: comments can remain italic,
keywords bold, warnings underlined, and errors reversed. `TERM=dumb` is the
strict plain-text endpoint and emits no SGR styling.

## Minimal partial theme

```fletch
{
    theme: 1,
    name: "paper",
    kind: "light",
    palette: { ink: "#24292f", accent: "#0550ae" },
    ui: {
        ul: { error: "#a40e26", warn: "#9a6700", info: "@accent" },
    },
    attrs: {
        text:    { fg: "@ink", mono: "plain" },
        keyword: { fg: "@accent", mono: "bold" },
    },
}
```

All other attrs inherit through the closed semantic fallback chain. Shipped
themes should not use this shortcut: they must spell all 54 rows explicitly so
coverage and palette changes remain reviewable.
