## Goals

Turn an editor that passes its gates into a release. Single-source the
version and freeze the `--version` / `-dumpversion` contracts with fixture
tests. Make release builds **byte-reproducible** — a pinned toolchain
container, `SOURCE_DATE_EPOCH` honored end to end, and a CI job that
rebuilds and byte-compares, which is where the determinism doctrine stops
being a testing convenience and becomes a property a stranger can verify.
Produce the family's distribution set: an AUR `PKGBUILD`, a Homebrew
formula for a tap, an RPM spec adapting `fuss.spec`, and a static-musl
release tarball. Publish checksums and detached signatures with a pinned
key story and verification instructions a user can follow without trusting
us. Write the README to one screen and the CHANGELOG in keep-a-changelog
form, curated retroactively against the campaign milestones. Freeze the
docs behind a link audit. Then walk the release checklist — which **is**
this sprint's Definition of Done — to a signed `v1.0.0` tag, and take the
post-release step that turns 60 sprints of honest `Defer:` sections into a
1.1 backlog.

## Deliverables

### 1. The version contract, single-sourced and audited

#### 1.1 One definition

`src/util/base.h` (where Sprint 0 put `YEW_VERSION`):

```c
#define YEW_VERSION       "1.0.0"
#define YEW_VERSION_MAJOR 1
#define YEW_VERSION_MINOR 0
#define YEW_VERSION_PATCH 0
_Static_assert(sizeof YEW_VERSION == sizeof "1.0.0", "version string width");
```

Everything derives from this: `--version`, `-dumpversion`, each man page's
`.TH` line, the newest CHANGELOG heading, the dist tarball name, the
PKGBUILD's `pkgver`, the formula's URL tag, the spec's `Version:`, the
`yew tutor` progress file's `version:` field, and `yew_version_hash` in
the syntax cache header.

#### 1.2 The target name — the only host-sniff site

`--version` must print the target, and yew has no target module yet.
**Assumption beyond the index entries:** Sprint 57 proved the musl profile
but landed no target-name accessor. This sprint lands one, mirroring the
sister project's discipline:

```c
/* src/util/target.h — closed set from 00-decisions.md.  No triple parser. */
typedef enum {
    YEW_TARGET_X86_64_LINUX_GNU,     /* "x86_64-linux-gnu"   (first)  */
    YEW_TARGET_ARM64_LINUX,          /* "arm64-linux"                 */
    YEW_TARGET_X86_64_LINUX_MUSL,    /* "x86_64-linux-musl"  (static) */
    YEW_TARGET_ARM64_MACOS,          /* "arm64-macos"                 */
} YewTarget;

YewTarget   yew_target_host(void);        /* the ONLY host-sniff site */
const char *yew_target_name(YewTarget t);
```

`yew_target_host()` is the single function permitted to contain
`#ifdef __x86_64__` / `__aarch64__` / `__APPLE__` / `__linux__` /
`__GLIBC__`. Anywhere else is a review rejection, and
`scripts/bans.sh` gains the grep. An unknown host is a **hard error**, not
a silent default — a binary that cannot name its own target must not
claim one.

**Pitfall:** musl defines no `__MUSL__`. Distinguish glibc from musl by
`#ifdef __GLIBC__` and treat its absence on Linux as musl; document that
reasoning in the file, because the next reader will look for the macro
that does not exist.

#### 1.3 The frozen output contracts

| Invocation | Contract, exact |
|---|---|
| `yew --version` | line 1 `yew 1.0.0 (x86_64-linux-gnu)`; line 2 `modules: lsp ai fuss plugins` (enabled set in `KNOWN_MODS` order, `modules: none` when empty); line 3 `License GPL-3.0-only; see LICENSE`. Nothing else. stdout. Exit 0 |
| `yew -dumpversion` | `1.0.0\n`, nothing else, exit 0 |
| `yew --version` | byte-identical to `yew --version` (it is the same binary through a symlink; `argv[0]` must not leak into the output) |

From 1.0.0 on, **changing these lines is an API break.** Build scripts and
packagers parse them. Fixtures in `tests/unit/test_version.c` plus
`scripts/smoke.sh` byte-compare all three forms; `smoke.sh`'s `version`
row moves from `yew 1.0.0-dev` to the three-line form and its
"stdout is exactly the two version lines" assertion becomes three.

#### 1.4 The syntax-cache consequence — stated, not discovered

Sprint 40's `.stab` header carries `yew_version_hash`, an FNV-1a-64 of
`--version` output. Changing that output **invalidates every cached
syntax table** on every user's machine at upgrade. That is correct, and it
is also free: the invalidation ladder's first rung is a header mismatch →
recompile. Two things must be proven rather than assumed:

1. A cache written by `1.0.0-dev` is discarded, not trusted, by `1.0.0`
   (fixture: a `.stab` with the old hash; assert one recompile and one
   `yew_log(INFO)`, no WARN, no error).
2. Because `--version` line 2 names the enabled modules, a `MODULES`
   change also invalidates. Also correct — a definition compiled against a
   different feature set is a different table. Fixture: build
   `MODULES="lsp"`, warm the cache, rebuild full, assert recompile.

#### 1.5 `ci/check-version.sh` — one number, nine copies

Asserts equality across: `YEW_VERSION`; `MAJOR.MINOR.PATCH` recomposed;
the `.TH` line of `yew.1`, `yew-fl.1`, `yew-pkg.1`; the newest
`CHANGELOG.md` release heading; `make dist`'s tarball name; `PKGBUILD`'s
`pkgver`; the Homebrew formula's `url` tag and `version` if present; the
RPM spec's `Version:` and its newest `%changelog` entry; and
`runtime/tutor/tutor.fl`'s `version:` field. A seeded one-place drift must
fail it. Wired into `make test` and the release lane.

### 2. Reproducible release builds — the determinism doctrine, cashed out

Invariant 5 has meant "same state → same grid" and "same input → same test
output" for sixty sprints. At the tag it must mean something a stranger
can check: **anyone who builds v1.0.0 in the pinned container gets a
binary whose sha256 matches the published one.**

#### 2.1 The pinned toolchain — `ci/Dockerfile.release`

```dockerfile
# Base pinned BY DIGEST, not by tag: tags move, and a moved base is a
# silently different binary.
FROM debian@sha256:<64 hex>
RUN apt-get update && apt-get install -y --no-install-recommends \
        gcc=<exact> binutils=<exact> make=<exact> \
        musl-tools=<exact> libc6-dev=<exact> ca-certificates \
 && rm -rf /var/lib/apt/lists/*
ENV LC_ALL=C LANG=C TZ=UTC SOURCE_DATE_EPOCH=0
WORKDIR /src
```

The image digest, the four package versions, and the container's own
sha256 are recorded in `docs/reproducible.md` and in the release notes.
Nothing in the image is fetched at build time; `make` never touches the
network (it never has — `src/unicode/tables.c` is checked in precisely so
a fresh clone with a C compiler suffices).

#### 2.2 What has to be true, and where it already is

| Hazard | Mechanism | Owner |
|---|---|---|
| Link order varies by filesystem | `$(shell find … \| sort)` | s00, already |
| Build date/time embedded | `__DATE__`/`__TIME__` banned, grep-gated | s00/s01, already |
| Absolute paths in `-D` | banned, grep-gated | s00, already |
| Absolute paths via `__FILE__` (used by `YEW_BUG`) | sources are named relatively (`src/foo.c`) by the Makefile's rules | s00, already |
| Absolute paths in DWARF `DW_AT_comp_dir` | `-ffile-prefix-map=$(CURDIR)=.` in the release build | **here** |
| Hash-order iteration reaching output | insertion-ordered `Strmap`, `yew_sort_stable`, no `qsort` | s00, already |
| Locale-dependent sort in any script | `LC_ALL=C` exported by the container and by `make dist` | **here** |
| gzip embeds mtime and OS byte | `gzip -n` | **here** |
| tar embeds uid/gid/mtime/order | `--sort=name --mtime=@$(SOURCE_DATE_EPOCH) --owner=0 --group=0 --numeric-owner` | **here** |
| Toolchain drift | the pinned container | **here** |

**`SOURCE_DATE_EPOCH`** is the release commit's committer date:
`git log -1 --pretty=%ct v1.0.0`. It is honored by `make dist`'s `tar`,
by the RPM build, and by nothing in the C sources — because nothing in the
C sources reads a build time, which is the point.

#### 2.3 `make dist` and `make release`

```make
VERSION      := $(shell sed -n 's/^#define YEW_VERSION "\(.*\)"/\1/p' src/util/base.h)
SOURCE_DATE_EPOCH ?= $(shell git log -1 --pretty=%ct)
export SOURCE_DATE_EPOCH LC_ALL=C TZ=UTC

dist: dist/yew-$(VERSION).tar.gz
dist/yew-$(VERSION).tar.gz:
	git archive --format=tar --prefix=yew-$(VERSION)/ HEAD \
	  | tar --delete --wildcards 'yew-$(VERSION)/.docs/*' -f - \
	  | gzip -n > $@
```

- The tarball's file list comes from **tracked files at the tag**, never
  from the working tree. `.docs/` (sprint files, audits) is excluded: it
  is the project's construction record, not the product, and it is ~1 MB
  of prose that would double the source tarball.
- `git archive` already normalizes uid/gid/mode and uses the commit time
  when `SOURCE_DATE_EPOCH` is exported, which is why it is preferred over
  a hand-rolled `tar` of the working tree.
- `make release` runs inside the container: `dist`, then a build and
  `make install DESTDIR=` staging per §3.4, then `SHA256SUMS`, then the
  signature (§4). It refuses to run outside the container (checks for a
  marker file the image writes) — a release built on a laptop is not
  reproducible by definition.

#### 2.4 The `repro` CI job — rebuild and byte-compare

Runs on two different runners, from a clean clone of the tag:

```sh
docker build -f ci/Dockerfile.release -t sagrel .
docker run --rm -v "$PWD:/src" sagrel make release
sha256sum -c dist/SHA256SUMS          # against the published file
```

Both runners' `SHA256SUMS` must be byte-identical, and both must match the
published one. On mismatch the job runs `scripts/bincmp.sh`, ~40 lines of
`cmp -l` plus `readelf -S` that prints the first differing offset and the
section it lands in — no `diffoscope`, which would be a dependency and
which is overkill when the answer is nearly always "a path leaked into
`.debug_str`".

**Pitfall.** Reproducibility is checked on the **unstripped** binary as
well as the stripped one. Stripping hides comp-dir and build-path leakage,
so a project that only compares stripped binaries can be irreproducible
for years and never know — and the RPM's `-debuginfo` subpackage (§3.3)
ships the unstripped one.

### 3. Packaging — the fuss distribution set, adapted

Four artifacts, matching the family's install story (AUR / Homebrew tap /
RPM repo) with a static tarball added because yew has an embedded
profile and fuss does not.

Prerequisite for all four: **`EXTRA_CFLAGS`**. Every distro injects its own
hardening flags. Sprint 0's Makefile sets `CFLAGS :=` with the locked
`-std=c11 -pedantic -Wall -Wextra -Werror -Wvla`; a packager doing
`make CFLAGS="%{optflags}"` silently drops all of them. This sprint adds:

```make
CFLAGS := -std=c11 -pedantic -Wall -Wextra -Werror -Wvla … $(EXTRA_CFLAGS)
LDFLAGS += $(EXTRA_LDFLAGS)
```

and every packaging file below uses `EXTRA_CFLAGS`, never `CFLAGS`. This is
the single most common way a packaged build differs from a tested one.

#### 3.1 `packaging/aur/PKGBUILD`

```bash
# Maintainer: mfw <mfwolffe@outlook.com>
pkgname=yew
pkgver=1.0.0
pkgrel=1
pkgdesc='Speed-first modal terminal editor with a built-in language (Fletch)'
arch=('x86_64' 'aarch64')
url='https://github.com/tenseleyFlow/yew'
license=('GPL-3.0-only')
depends=('glibc')
makedepends=('gcc' 'make')
optdepends=('git: FUSS mode, yew pkg, and git integration'
            'curl: cloud AI backends (local backends need nothing)'
            'clang: clangd, the C language server')
source=("$pkgname-$pkgver.tar.gz::$url/releases/download/v$pkgver/$pkgname-$pkgver.tar.gz"
        "$pkgname-$pkgver.tar.gz.asc::$url/releases/download/v$pkgver/SHA256SUMS.asc")
sha256sums=('<sha256 of the source tarball>' 'SKIP')
validpgpkeys=('<40-hex release key fingerprint>')

build()   { cd "$pkgname-$pkgver"; make PREFIX=/usr EXTRA_CFLAGS="$CFLAGS"; }
check()   { cd "$pkgname-$pkgver"; make test YEW_SKIP_NET=1; }
package() {
  cd "$pkgname-$pkgver"
  make DESTDIR="$pkgdir" PREFIX=/usr install
  install -Dm644 LICENSE   "$pkgdir/usr/share/licenses/$pkgname/LICENSE"
  install -Dm644 README.md "$pkgdir/usr/share/doc/$pkgname/README.md"
  cp -r docs/manual        "$pkgdir/usr/share/doc/$pkgname/manual"
}
```

**Pitfalls.**
- `.SRCINFO` must be regenerated (`makepkg --printsrcinfo > .SRCINFO`) and
  committed **in the same commit**; the AUR rejects a push whose `.SRCINFO`
  disagrees with the `PKGBUILD`, and the failure message does not say so
  clearly.
- `arch=()` lists only targets we actually gate in CI. `aarch64` is there
  because `arm64-linux` is a locked, CI-gated target; anything else would
  be a claim we cannot back.
- `check()` must not need the network or a language server. The `lsp`
  milestone lane needs `clangd`; `make test` must therefore honor a
  documented opt-out for the packaging context — hence `YEW_SKIP_NET=1`,
  which skips the clangd lane and **nothing else**, and which prints what
  it skipped rather than passing silently.
- `$srcdir` versus `$pkgdir`: everything installed goes under `$pkgdir`;
  a stray absolute path installs onto the *builder's* system.
- Do not add a `yew` line to `package()` — the Makefile's `install` target
  already creates the symlink, and creating it twice is how the two
  disagree after a refactor.

#### 3.2 `packaging/brew/yew.rb` — the tap

Tap name `tenseleyFlow/homebrew-yew`, so the user does
`brew tap tenseleyFlow/yew && brew install yew` — the same shape as
`brew tap FortranGoingOnForty/fuss`.

```ruby
class yew < Formula
  desc "Speed-first modal terminal editor with a built-in language (Fletch)"
  homepage "https://github.com/tenseleyFlow/yew"
  url "https://github.com/tenseleyFlow/yew/releases/download/v1.0.0/yew-1.0.0.tar.gz"
  sha256 "<sha256>"
  license "GPL-3.0-only"

  depends_on "make" => :build
  # No runtime deps: git, curl and language servers are optional and are
  # detected at run time.  Listing them would install a git for a user
  # who only wants an editor.

  def install
    system "make", "PREFIX=#{prefix}"
    system "make", "install", "PREFIX=#{prefix}"
    (pkgshare/"manual").install Dir["docs/manual/*"]
  end

  test do
    assert_match "yew #{version}", shell_output("#{bin}/yew --version")
    assert_equal "#{version}\n", shell_output("#{bin}/yew -dumpversion")
    (testpath/"a.txt").write "hello\n"
    (testpath/"s.fl").write %q(for p in files { let b = buf.open(p)
                                edit { b.line(1).append(" world") }
                                b.save() })
    system bin/"yew", "--batch", testpath/"s.fl", testpath/"a.txt"
    assert_equal "hello world\n", (testpath/"a.txt").read
  end
end
```

**Pitfalls.**
- Homebrew builds with `make -j$(nproc)` by default. fuss hit exactly this
  and answered with `.NOTPARALLEL`; yew must **not** need that escape
  hatch — the Makefile's order-only `| dirs` prerequisite and per-object
  rules are already parallel-safe, and §Testing proves it with a
  `make -j16` from clean on every target. Adding `.NOTPARALLEL` would make
  a full build minutes slower for everyone to paper over one recipe.
- `license "GPL-3.0-only"` must be the exact SPDX id; `brew audit --strict`
  rejects `GPL-3.0`.
- The `test do` block must exercise a real product surface. A formula
  whose test is `--version` proves the binary linked, not that it works;
  the `--batch` round-trip above proves the editor edits and saves, in four
  lines and no terminal.
- macOS installs man pages under `#{man}`; the Makefile's
  `$(PREFIX)/share/man` is correct for Homebrew's prefix layout — do not
  special-case it.

#### 3.3 `packaging/rpm/yew.spec` — adapting `fuss.spec`

```spec
Name:           yew
Version:        1.0.0
Release:        1%{?dist}
Summary:        Speed-first modal terminal editor with a built-in language

License:        GPL-3.0-only
URL:            https://github.com/tenseleyFlow/yew
Source0:        %{url}/releases/download/v%{version}/%{name}-%{version}.tar.gz

BuildRequires:  gcc >= 8
BuildRequires:  make

%description
yew is a modal terminal editor written in C11 with no dependencies
beyond libc: a bespoke terminal layer, text engine, regex engine, syntax
highlighter, LSP client, and its own scripting language, Fletch, in which
recorded macros are readable source code.

%prep
%autosetup

%build
make PREFIX=%{_prefix} EXTRA_CFLAGS="%{optflags}" %{?_smp_mflags}

%check
make test YEW_SKIP_NET=1

%install
make DESTDIR=%{buildroot} PREFIX=%{_prefix} install
install -Dm644 README.md %{buildroot}%{_docdir}/%{name}/README.md
cp -r docs/manual %{buildroot}%{_docdir}/%{name}/manual

%files
%license LICENSE
%doc %{_docdir}/%{name}
%{_bindir}/yew
%{_bindir}/yew
%{_mandir}/man1/yew.1*
%{_mandir}/man1/yew-fl.1*
%{_mandir}/man1/yew-pkg.1*
%{_mandir}/man7/yew-regex.7*
%{_datadir}/%{name}/

%changelog
* Fri Jul 31 2026 mfw <mfwolffe@outlook.com> - 1.0.0-1
- First release
```

Adapted from `fuss.spec`; the deliberate departures, each with a reason:

| fuss.spec | yew.spec | Why |
|---|---|---|
| `%global debug_package %{nil}` | **omitted** — debuginfo is built | fuss disabled it to work around gfortran's debuginfo extraction. A C editor's users file crashes; `yew-debuginfo` is worth more than a simpler spec. It also gives §2.4's unstripped-binary reproducibility check a consumer |
| no `%check` | `%check make test` | fuss ships no test suite. yew's is the product's main claim; a package built from sources that fail their own tests must not exist |
| `install -Dm755 fuss` by hand | `make install` | one install path, tested by `make install DESTDIR=…` in CI, not two that drift |
| `Requires: git`, `Requires: fzf` | `Recommends: git`, `Suggests: curl` | git and curl are optional and degrade gracefully with a pinned message (00-decisions.md). A hard `Requires` would be a lie about the dependency model |
| README only under `%{_docdir}` | README + `docs/manual/` | the manual is a shipped deliverable |

**Pitfalls.**
- `%{optflags}` must reach the compiler through `EXTRA_CFLAGS`, never
  `CFLAGS` — see §3's preamble. Passing it as `CFLAGS` silently drops
  `-std=c11 -Werror` and builds a program we never tested.
- `%changelog` dates: the weekday must match the date and entries must be
  in **descending** order. `fuss.spec` carries several entries whose
  weekday and date disagree and whose ordering is not monotonic; `rpmlint`
  flags both, and some builders escalate. Generate the line with
  `LC_ALL=C date -u -d @$SOURCE_DATE_EPOCH '+%a %b %d %Y'`.
- Man pages are compressed by the RPM macros, so `%files` globs must end
  `.1*`, not `.1`.
- `%autosetup` needs the tarball's top directory to be `%{name}-%{version}`
  — which §2.3's `--prefix` guarantees.

#### 3.4 The static-musl tarball

`yew-1.0.0-x86_64-linux-musl.tar.gz`, built in the pinned container:

```
yew-1.0.0-x86_64-linux-musl/
  bin/yew                  static, stripped
  bin/yew -> yew           a real symlink
  share/man/man1/{yew,yew-fl,yew-pkg}.1
  share/man/man7/yew-regex.7
  share/yew/runtime/       init.fl, syntax/, themes/, tutor/
  share/doc/yew/{README.md,manual/,CHANGELOG.md}
  LICENSE
```

Built `CC=musl-gcc` with `-static`, `MODULES="lsp ai fuss plugins"`, then
verified: `ldd` reports "not a dynamic executable"; `file` says
"statically linked"; stripped size within Sprint 57's ≤ 1.5 MiB budget;
`yew --version` prints `(x86_64-linux-musl)`.

**Pitfalls.**
- Package the symlink **as a symlink** — `tar` without `--dereference`
  does this, `--dereference` would ship two 1.4 MiB copies and break the
  "one binary, two names" contract.
- The runtime tree is not optional. `yew` errors naming
  `YEW_RUNTIME_DIR` when `init.fl` is missing (s36 row 1), so a tarball
  without `share/yew/runtime/` produces a binary that refuses to
  start. The extraction instructions in the README say where to put it or
  how to set `YEW_RUNTIME_DIR`.
- Static glibc would break `getpwuid` (NSS wants shared objects), and
  Sprint 19 resolves `$SHELL` through `getpwuid(getuid())->pw_shell`.
  Under musl this is fine and the reason belongs in a comment, because it
  is exactly the sort of thing someone "simplifies" back to glibc.

### 4. Checksums and signing — the pinned approach

**Decision: one `SHA256SUMS` file, one detached OpenPGP signature over
it, and a signed annotated tag.** Rejected: signing each artifact
individually (N signatures to fetch and verify, and N chances to verify
the wrong one); minisign or signify (better tools, but they ask a user to
install something before they can check anything, and `gpg` is already on
the machines that consume AUR and RPM).

Published per release:

```
dist/
  yew-1.0.0.tar.gz                           source
  yew-1.0.0-x86_64-linux-musl.tar.gz         static
  SHA256SUMS                                     one line per artifact
  SHA256SUMS.asc                                 detached, armored
```

- `SHA256SUMS` is produced with `LC_ALL=C sha256sum` over the artifacts in
  **sorted name order** so the file itself is reproducible.
- The tag is annotated **and signed**: `git tag -s v1.0.0 -F <changelog
  excerpt>`. Signing the tag is not optional here (unlike the sister
  project, where it was noted as nice-to-have) because §5's install
  instructions tell users to verify, and instructions to verify against an
  unsigned artifact are theater.
- **Key publication, three places, all of which a user can reach without
  trusting the download:** the full ASCII-armored public key in `KEYS` at
  the repo root; the 40-hex fingerprint in `README.md`'s install section
  and in `docs/verify.md`; the fingerprint in the tag's own message. The
  PKGBUILD's `validpgpkeys` pins the same fingerprint, so an AUR user gets
  the check for free.
- **Key policy** in `docs/verify.md`: algorithm and length, creation date,
  expiry, that the signing subkey is kept off the CI machines (CI never
  signs — `make release` produces artifacts, a human signs them), and what
  happens on rotation (the new key is signed by the old one, both stay in
  `KEYS`, and the transition is announced in the CHANGELOG).

Verification instructions, reproduced verbatim in `README.md` and
`docs/verify.md`:

```sh
gpg --recv-keys <FINGERPRINT>            # or: gpg --import KEYS
gpg --verify SHA256SUMS.asc SHA256SUMS
sha256sum -c SHA256SUMS --ignore-missing
```

And, for anyone who would rather trust arithmetic than a key:

```sh
docker build -f ci/Dockerfile.release -t sagrel .
docker run --rm -v "$PWD:/src" sagrel make release
diff dist/SHA256SUMS <(curl -sL <release-url>/SHA256SUMS)
```

That second block is why §2 exists.

### 5. `README.md` — one screen

Order, and nothing else: **what it is** (two paragraphs — a modal terminal
editor in C11 with no dependencies beyond libc, and Fletch, the language
it is configured and scripted in, in which a recorded macro is readable
source) → **why it exists** (one paragraph, no manifesto: because the
editors that are fast are not scriptable in a language worth reading, and
the editors that are scriptable are not fast; and because a piece of
software that holds your files should be auditable end to end by one
person) → **install** (AUR, Homebrew tap, RPM repo, static tarball, build
from source — five short blocks, matching fuss's README shape) →
**verify** (the three commands from §4) → **quickstart** (six lines:
`yew file.txt`, the mode chip, `i`, Esc, `:w`, and `yew tutor`) →
**status** (the honest four-target table) → **license** (GPL-3.0-only, one
line, link to LICENSE).

The status table's caveat column is filled from the Sprint 59 closeout
evidence and may not be empty where caveats exist:

| Target | Status | Caveats |
|---|---|---|
| `x86_64-linux-gnu` | supported, CI-gated, perf-gated | — |
| `arm64-linux` | supported, CI-gated | perf budgets measured, not gated (the designated runner is x86_64) |
| `x86_64-linux-musl` | supported, CI-gated, static | *from `closeout-F15-ci.md`* |
| `arm64-macos` | supported, CI-gated | *from `closeout-F02-terminal.md` and `closeout-F15-ci.md`* |

**Rules.** No feature list longer than the install section. No
screenshots that will not be regenerated (a stale screenshot is a
documentation bug that survives every check in this repo). No comparison
table against other editors. No claim not backed by a gate — "p99 keypress
latency under 5 ms on the reference runner" is legitimate because
Sprint 56 gates it; "the fastest terminal editor" is not.

### 7. Docs freeze and the link audit

**The freeze.** After the release-candidate commit, `docs/`, the man
pages, `README.md`, and `CHANGELOG.md` accept only changes that are
typo-level and semantics-free, prefixed `docs:` and reviewed as such. A
content change reopens the checklist. The freeze date and commit are
recorded in `docs/reproducible.md`.

**`scripts/check-links.sh`**, wired into `make test` and the release lane:

1. Every relative link in `README.md`, `docs/**`, and `CHANGELOG.md`
   resolves to a file in the tree.
2. Every anchor link (`file.md#section`) names a heading that exists.
3. Every man-page cross-reference (`yew-fl(1)`, `git(1)`,
   `yew-regex(7)`) names an installed page or a page from a documented
   `Recommends`/`Suggests`.
4. Every `see man <page>` and every `see <doc>` string in `src/` resolves.
5. Every `docs/manual/` chapter is linked from `README.md` or from another
   chapter — an orphan chapter is a chapter nobody reads.
6. No absolute URL points at a `blob/main` or `blob/trunk` path (those
   rot); links into the repo use `blob/v1.0.0`.
7. **`grep -rnE 'Sprint [0-9]+' src/` returns nothing.** Sprint 58's F15
   appendix enumerated every survivor; at 1.0 every sprint has landed, so
   a message promising a future sprint is a lie about an implemented
   surface — invariant 3 inverted. Permanent non-goals keep their
   messages, which by construction name no sprint (Sprint 20's regex text
   is the model).

External URLs are checked once, by hand, at freeze time and recorded; the
script does not fetch (a CI lane that fails because someone else's site is
down is a lane people learn to ignore).

### 8. The post-release step — the tag is not the finish line

Still this sprint, after the tag:

- **Freeze baselines as 1.0.0 reference points.** One commit,
  `freeze 1.0.0 baselines`, re-committing `tests/perf/baselines/*` and
  every ratchet file as they stood at the tag. Future regressions are
  measured against the release, not against a moving trunk.
- **`scripts/collect-deferrals.sh`** greps all 61 sprint files' `Defer:`

  itself out of sixty sprints of honest deferral notes — which is why
  every sprint file had a `Defer:` section. Reviewed by hand once; the

- **Record the release.** `docs/reproducible.md` gains the final row:
  tag, commit, `SOURCE_DATE_EPOCH`, container digest, toolchain versions,

### 9. Defer

- Everything in `.docs/backlog-1.1.md`: threads in the core, FreeBSD as a
  fifth target, embedded language highlighting (`s41_5`), Unicode 17.0.0,
  snippet expansion, markdown rendering in panels, an interactive terminal
  buffer, filesystem watching, plugin dependencies, native plugins, VM
  resource limits, multi-session workspace merge, indexed project search,
  frecency ranking. All of these already hard-error or are documented
  non-goals; they stay that way past the tag.
- Distribution channels beyond the four: nixpkgs, Debian, Alpine,

  package, and this sprint ships exactly the set the family already

- A signed release-artifact transparency log, reproducible-builds.org

## Testing Strategy

- **Contract fixtures** (`tests/unit/test_version.c`, `scripts/smoke.sh`):
  all three invocation forms byte-compared, on every target and through
  both `yew` and the `yew` symlink; `MODULES=""` and each single-module
  build asserted for line 2; a seeded `argv[0]` leak must fail.
- **`ci/check-version.sh`** with nine seeded-drift fixtures — one per
  copy — each of which must fail the script.
- **Syntax-cache invalidation** (§1.4): the stale-hash fixture and the
  `MODULES`-change fixture, each asserting exactly one recompile and no
  error path.
- **Reproducibility**: the `repro` job on two runners, comparing stripped
  **and** unstripped binaries and both tarballs; a seeded violation
  (`-D BUILD_HOST=$(hostname)` added locally) must make it fail, and
  `bincmp.sh` must name the offending section.
- **Parallel-build safety**: `make -j16` from a clean tree, ten times, on
  each of the four targets — no missing-directory failures, no interleaved
  header generation, final binary sha256 identical to a `-j1` build. This
  is what buys the absence of `.NOTPARALLEL`.
- **Package smoke, per artifact, in a clean container with the network off
  after fetch:**
  - AUR: `makepkg -si` in an Arch container; `namcap` on the built package;
    `.SRCINFO` regenerated and diffed.
  - Homebrew: `brew install --build-from-source ./yew.rb` then
    `brew test yew` and `brew audit --strict --new yew` on macOS.
  - RPM: `rpmbuild -ba` in a Fedora container; `rpmlint` on the spec, the
    binary RPM, and the debuginfo RPM; `dnf install` of the built RPM then
    the §DoD walkthrough.
  - musl tarball: extract into `/opt`, run with and without
    `YEW_RUNTIME_DIR` set (the second must produce the s36 error naming
    the variable, not a crash).
- **Staged-install correctness**: `make install DESTDIR=/tmp/stage
  PREFIX=/usr` then run the staged binary with `YEW_RUNTIME_DIR` pointed
  into the stage — the editor must open a file, highlight it, run a
  `--batch` script, and find its man pages via a `MANPATH` into the stage.
  Nothing may resolve back into the build tree.
- **Signature verification** performed from a clean machine with only the
  fingerprint: import from a keyserver, verify `SHA256SUMS.asc`, check the
  sums, and verify the tag (`git verify-tag v1.0.0`).
- **Link audit**: `check-links.sh` green; seeded broken relative link,
  broken anchor, orphan chapter, `blob/trunk` URL, and a leftover
  `Sprint 42` string in `src/` each must fail it.
- **CHANGELOG generation**: `gen-changelog-limits.sh` run twice
  byte-identical; a deferral added to `deferrals.md` without regenerating
  must fail `ci/check-version.sh`.
- **The full suite** on all four targets at the RC commit: unit, script,
  pty, roundtrip, fletch conformance, torture, audit, tutor, manual, perf,
  determinism, bans, modules, `MODULES=""`, and the `lsp` milestone lane.
